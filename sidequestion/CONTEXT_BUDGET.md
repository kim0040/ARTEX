# 곁길의 긴 대화와 맥락 예산

초보 안내: 곁길 질문(`/btw`)은 메인 에이전트 맥락의 사본으로 답합니다. 탐색 그래프에 의도나 발견을 쓰지 않습니다. 이 문서는 그 사본이 모델 창을 넘지 않게 자르고 요약하는 규칙입니다.

2026-09-11 수정. 예전 구현은 요청 JSON 의 글자 수를 token 으로 보고, 메인 작업의 32K 출력 예약을 물려받았습니다. 그래서 HTML, JS, 도구 결과가 많으면 정상적인 곁길 질문을 일찍 거절했습니다.

## 오픈소스 구현 대조

- [Grok CLI 곁길 맥락](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자·도우미 텍스트에서 조각을 뽑습니다. 글자 예산은 약 2000, 항목마다 최대 400자입니다. 이 경로에는 연속된 곁길 문답 기록을 두지 않습니다.
- [Grok CLI 독립 요청](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 독립 취소 신호. 모델이 지원하면 출력 상한 2048 tokens. 도구를 주지 않습니다.
- [Grok CLI 메인 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): token 을 추정하고, 최근 내용을 남기고, 새 내용을 옛 요약에 반영하며, 턴을 넘는 절단을 처리합니다.
- [OpenCode 세션 압축](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청 추정, 출력/버퍼 예약, 최근 내용과 굴러가는 요약, 도구 없는 요약 요청. 그 구현의 기본은 최근 예산 8000, 요약 출력 상한 4096 tokens 입니다.
- [OpenCode 넘침 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 도우미 출력이 아직 시작되지 않았을 때만 넘침 복구를 시도하고, 복구 뒤의 호출은 같은 복구 경로로 다시 들어가지 않습니다.

ARTEX 는 독립 출력 예산, 최근 내용과 굴러가는 요약, 제한된 복구를 가져왔습니다. norma v0.3.6 의 구조화 메시지와 도구 짝을 유지하고, Grok 의 텍스트 발췌를 그대로 베끼지 않습니다. OpenCode 의 메인 세션 압축 이벤트를 ARTEX 메인 transcript 에 쓰지 않습니다.

## 요청 예산과 실행

- 메시지는 norma 의 내용 블록 UTF-8 바이트 추정과 4/3 여유를 그대로 씁니다. 시스템 프롬프트, 도구 schema, 메시지 포장 오버헤드를 더합니다. 추정은 모델의 정확한 token 수가 아닙니다.
- 곁길 출력 기본 상한은 8192 tokens 이고, 메인 설정에 이미 있는 출력 상한을 넘지 않습니다. 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS` 로 256–32768 상한을 둘 수 있습니다. 제품 기본 모델이나 메인 작업 파라미터는 바꾸지 않습니다.
- 입력 예산은 맥락 창에서 출력 상한과 안전 여유를 뺀 값입니다. 창을 모르면 플랫폼 기본 200K 를 씁니다. 안전 여유는 창의 5%이고, 최소 128, 최대 8192 tokens 입니다.
- 성공한 문답은 증가하는 순번으로 한 번에 최대 20조를 읽습니다. 원문은 최대 20조를 남기고, 그 token 예산은 입력 예산의 1/4 이하이며 16K 를 넘지 않습니다.
- 넘치는 문답은 굴러가는 요약으로 갱신합니다. 요약에는 기록 출처와 맥락 시각이 있습니다. 과거의 도우미 답은 새 도구 증거와 같지 않으며, 충돌하면 최신 메인 스냅샷을 우선합니다.
- 메인 맥락이 여전히 길면 사본의 오래된 메시지만 요약하고, 최근은 최대 8K tokens 를 남깁니다. 자르는 지점이 도구 호출과 결과를 가르지 않습니다. 너무 큰 한 조는 통째로 요약에 들어갑니다.
- 요약 입력은 실제로 남은 창에 맞춰 UTF-8 안전하게 나눕니다. 출력 상한은 2048 tokens 입니다. 빈 요약, 절단, 도구 호출, 요약 예산 초과는 캐시에 쓰지 않습니다. 곁길 한 번에 요약 호출은 최대 12번이고, 같은 120초 제한을 받습니다. 상한에 닿으면 분명히 실패하며 무한 반복하지 않습니다.
- 모델이 처음 맥락 초과를 돌려주고 아직 텍스트나 도구 호출을 내지 않았으면, 더 줄인 뒤 최대 한 번 재시도합니다. 추정 크기가 줄지 않으면 복구를 바로 멈춥니다. 다른 모델 오류와 일부만 나온 스트림은 이 복구를 일으키지 않습니다.
- 이미 받은 사용량은 요약, 실패 시도, 취소 때를 포함해 같은 곁길 요청에 더합니다. Provider 가 사용량을 안 주면 0만 기록할 수 있고, 추정을 실제 사용량인 것처럼 두지 않습니다.

## 저장과 화면

`side_question_sessions.memory` 는 옛 문답 요약, 덮인 ordinal, 스냅샷 신원별로 캐시한 메인 맥락 요약을 저장합니다. `side_question_requests.context_info` 는 준비 단계, 실제 재생 조 수, 요약 사용, 예산 추정을 저장합니다.

요약은 원래 요청이 아직 실행 중이고 정리 버전이 맞을 때만 저장합니다. 비우기는 캐시도 지우고, 늦은 쓰기가 이미 지운 데이터를 되돌리지 않습니다. 새 스냅샷은 옛 스냅샷 요약을 다시 쓰지 않습니다. 요약 필드는 v3 작업 아카이브에 함께 저장됩니다. 옛 v3 에 필드가 없으면 빈 객체를 채우고, v1/v2 는 계속 호환합니다.

POST 는 먼저 요청을 받아 돌려주고, 준비와 압축은 백그라운드에서 합니다. 입장 잠금이나 데이터베이스 트랜잭션을 잡지 않습니다. SSE/기록은 준비, 문답 정리, 사본 압축, 답변 단계를 보여 줍니다. 압축 실패는 그 곁길 요청의 실패 종료 상태로 저장됩니다. 프론트는 오류를 남기고 이번 실패 질문의 초안을 되돌리며, 떠 있는 알림으로 입력칸을 가리지 않습니다. 기록 폴링이 제출 오류를 지우지 않습니다.
