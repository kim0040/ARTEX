# 처음 읽는 ARTEX 한국어 학습판

이 문서는 **코드를 읽고 샘플 화면을 이해하는 순서**를 안내합니다. 실제 온라인 대상을 조사하는 절차가 아닙니다. 이용 범위와 출처는 [포크·라이선스 안내](포크-라이선스-안내.md)를 먼저 확인하세요.

## 먼저 알아둘 네 가지

| 이름 | 쉬운 설명 |
| --- | --- |
| 화면 `web` | 버튼과 표를 보여 주는 부분입니다. 브라우저에서 실행됩니다. |
| 서버 `server` | 화면의 요청을 받아 처리하고 결과를 돌려주는 부분입니다. Go 프로그램입니다. |
| 저장소 `db` | 작업·자산·기록을 PostgreSQL 데이터베이스에 읽고 쓰는 부분입니다. |
| 에이전트 `agent` | 모델에 맥락을 주고 도구 호출과 결과 기록을 연결하는 부분입니다. |

사용자가 버튼을 누르면 대체로 `화면 → web/src/lib/api.ts → server의 처리 함수 → db → 화면` 순서로 이동합니다. AI가 관여하지 않는 목록 조회나 설정 저장도 있습니다. `agent`를 거치는 처리는 그중 일부입니다.

## 파일을 읽는 순서

1. [README의 용어와 구조](../README.md#프로그램이-어떻게-짜여-있는지)를 읽습니다. 처음에는 큰 그림과 디렉터리 표만 봐도 됩니다.
2. [cmd/artex/main.go](../cmd/artex/main.go)의 `main`을 읽습니다. 설정을 불러오고 서버를 여는 입구입니다.
3. [server/manager.go](../server/manager.go)의 `NewManager`를 읽습니다. 서버가 함께 사용할 저장소와 기록 프록시를 준비합니다. 작업 엔진은 `server/server.go`의 `New`가 만듭니다.
4. [server/server.go](../server/server.go)의 경로 등록을 봅니다. `/api/...` 주소가 어느 처리 함수로 연결되는지 찾습니다.
5. 관심 있는 화면의 파일을 `web/src/app`에서 찾고, 그 화면이 부르는 `api` 함수를 [web/src/lib/api.ts](../web/src/lib/api.ts)에서 확인합니다.
6. 데이터를 읽거나 저장하는 실제 SQL은 `db`에서 확인합니다. [db/schema.sql](../db/schema.sql)은 데이터 표의 구조입니다.
7. AI와 작업 실행이 궁금하면 [server/engine.go](../server/engine.go), [agent/planner.go](../agent/planner.go), [agent/worker.go](../agent/worker.go)를 읽습니다.

전체 파일을 순서 없이 모두 읽을 필요는 없습니다. 화면 하나에서 시작해 호출하는 함수만 따라가면 됩니다. 함수 이름과 JSON 키가 영어인 것은 다른 코드와 주고받는 이름을 보존하기 위해서입니다.

## 화면 하나를 따라 읽는 예

- **작업 목록 보기:** `web/src/app/(main)/function/tasks/page.tsx`가 `api.tasks()`를 부릅니다. `web/src/lib/api.ts`가 `/api/tasks`로 요청을 보내고, `server/server.go`에 등록된 처리 함수가 작업 목록을 반환합니다. 화면은 받은 데이터를 표로 그립니다. 이 조회 자체가 모델 실행을 시작하는 것은 아닙니다.
- **스킬 ZIP 올리기:** `web/src/app/(main)/system/skills/page.tsx`가 `api.uploadSkill()`을 부르고, 서버의 `fsUploadSkill`이 ZIP 구조와 이름을 검사합니다. 같은 이름이 있으면 HTTP 409를 반환합니다. 화면은 문장의 언어가 아니라 이 상태 코드로 덮어쓰기 확인을 띄웁니다. 확인했을 때만 다시 요청합니다.

## 그래프가 두 개인 이유

**자산 그래프**는 회사 단위로 공유하는 대상 장부입니다. **탐색 그래프**는 작업 하나에서 어떤 목표와 생각을 거쳐 무엇을 했는지 남기는 기록입니다. 회사의 같은 자산을 다른 작업이 다시 다룰 수 있으므로 두 기록의 수명이 다릅니다. 둘은 앵커라는 연결로 묶입니다.

플래너는 다음에 할 작업 단위인 **의도**를 만들고, 워커는 대기 중인 의도 하나를 받아 실행한 뒤 결과를 기록합니다. 메인 에이전트는 사람과의 대화를 담당합니다. 워커 한 번의 종료와 전체 작업의 종료는 같은 뜻이 아닙니다.

트래픽 기록은 별도 SQLite 색인과 파일에 저장됩니다. 발견에 고정한 증거 스냅샷과 일반 트래픽 목록도 구분됩니다. 목록에서 기록을 지웠다고 다른 저장소의 증거까지 모두 지워졌다고 생각하면 안 됩니다.

## 낯선 용어를 쉬운 말로

| 용어 | 뜻 |
| --- | --- |
| API | 화면과 서버가 요청·결과를 주고받는 약속입니다. |
| JSON | 이름과 값을 묶어 데이터를 주고받는 글 형식입니다. |
| SSE | 서버가 새 소식을 브라우저에 계속 보내는 연결입니다. |
| JWT | 로그인 상태를 증명하기 위해 요청에 붙이는 서명된 토큰입니다. 비밀처럼 취급합니다. |
| 스키마 | 데이터베이스 표와 열의 구조입니다. |
| 멱등 | 같은 처리를 다시 해도 결과가 불필요하게 중복되지 않는 성질입니다. |
| 고루틴 | Go에서 동시에 작업을 진행하는 실행 단위입니다. |
| 맥락·컨텍스트 | 모델이 이번 질문을 이해할 때 참고하는 메시지와 자료입니다. |
| 프록시 | 통신 중간에서 요청을 전달하는 부분입니다. 기록용 프록시는 요청·응답을 저장합니다. |
| 장애 조치 | 선택한 모델이 실패하면 미리 정한 다른 설정으로 이어 시도하는 동작입니다. |
| 목업 | 실제 서버 대신 샘플 응답을 돌려주는 화면 확인용 모드입니다. |
| 하네스 | 모델 호출·도구 실행·기록·중지를 묶어서 관리하는 실행 틀입니다. |

## 샘플 화면을 보는 방법

```sh
cd web
npm ci
NEXT_PUBLIC_MOCK=1 npm run dev
```

터미널에 나온 로컬 주소를 엽니다. 이 모드는 데이터베이스와 모델 키 없이 샘플 화면을 볼 수 있습니다. 표시된 발견·트래픽·토큰 사용량은 실제 검사 결과가 아닙니다. 새로고침이나 개발 서버 재시작 때 샘플 상태가 바뀔 수 있습니다.

목업에서 버튼이 잘 동작해도 실제 데이터베이스 저장이나 모델 실행까지 검증된 것은 아닙니다. 코드 변경 후에는 종류에 맞는 검사와 독립 로컬 환경의 검증을 따로 해야 합니다.

## 무엇이 번역되고 무엇이 원문인가

화면의 고정 안내·상태·날짜·접근성 문구, 코드 설명 주석, 보고서의 표와 제목은 한국어 대상입니다. 시스템 프롬프트와 `skills/` 문서, 라이선스 전문, 사용자가 넣은 데이터, 도구가 반환한 증거, 과거 기록은 원문을 보존합니다. AI가 작성하는 자유로운 답변과 보고서 본문은 모델과 설정의 영향을 받으므로 한국어 출력 여부를 별도로 확인해야 합니다.

설명이 실제 코드와 다르면 설명을 고쳐야 합니다. 한국어가 들어 있다는 이유만으로 설명이 정확하거나 초보자에게 쉽다고 판단하지 않습니다.
